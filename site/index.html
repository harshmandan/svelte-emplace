Svelte 5 · 180 lines · no dependencies

The best portal for Svelte 5.

Put a modal, tooltip or toast anywhere on the page. It is made right where you want it, instead of being made somewhere else and moved over. So nothing jumps, and nothing reloads.

Rendered in the page, then moved

<main>
  <div class="tip">         --+   rendered here
                              |
<body>                        |
  <div id="layer">            |
    <div class="tip">       <-+   moved here after

Mounted in place, when needed

<main>
  (nothing)

<body>
  <div id="layer">
    <div class="tip">             mounted here

Get started

1 · Install

npm i svelte-emplace

Needs Svelte 5.

2 · Use it

<script>
  import { Emplace }
    from 'svelte-emplace';
</script>

<Emplace>
  <div class="modal">…</div>
</Emplace>

No settings. It goes to the bottom of the page.

3 · Pick a spot — optional 

<h1 data-emplace="title"></h1>

<Emplace to="title">
  {data.title}
</Emplace>

Use to when it has to go in one exact place, like a header. Modals and toasts do not need it.

What you get

Six things, and why they happen. Compared with svelte-portal, which moves the element instead of making it in place.

Tooltips appear in the right spot

Code that positions or focuses something runs the moment that thing appears on the page. If it is made inside your component and then moved to the target, the code has already run — it measured the place it was made, and it does not run a second time. Mounted straight into the target, the first measurement is the final one.

svelte-portal
Measures the place it was written in, then gets moved. It sits in the wrong position until you measure again yourself.
svelte-emplace
Measures the place it lands in. Correct on the very first frame.
<Emplace to="#layer">
  <div {@attach (node) =>
    computePosition(button, node)}>
    Copied
  </div>
</Emplace>

Nothing reloads

Moving an element means taking it out of the page and putting it back somewhere else. The browser treats what comes back as brand new. Anything alive inside it starts from scratch.

svelte-portal
A video starts again, a payment box reloads, and a half-typed field loses both the text and the cursor.
svelte-emplace
The element is never taken out, so nothing inside it restarts.
<Emplace>
  <dialog>
    <iframe src={checkout}></iframe>
  </dialog>
</Emplace>

Nothing extra is added

To move something you need a handle on it, so it gets wrapped in an element first. That wrapper travels with it and stays in your page, sitting between the target and your own markup.

svelte-portal
Adds a <div> around your content, which breaks flex and grid spacing and any CSS expecting your element to be a direct child.
svelte-emplace
Adds nothing you can see. Position is held by invisible markers, so your markup is a direct child of the target.
<!-- what ends up in the page -->
<nav class="flex gap-2">
  <button>Save</button>
</nav>

You choose the order

Several parts of your app often fill the same spot — a row of buttons, a stack of toasts. If the order follows whichever part loaded first, it changes as people move around the app and as code loads late.

svelte-portal
Order follows load order, and there is no way to set it.
svelte-emplace
Each one takes a number and the order is worked out fresh every time something is added or removed, so it never drifts.
<Emplace to="toolbar" priority={10}>
  <button>Save</button>
</Emplace>

<Emplace to="toolbar">
  <button>Cancel</button>
</Emplace>

Two places at once

An element on a page has exactly one parent. So moving it can only ever put it in one place. Making it can happen twice.

svelte-portal
One place only. To fill a phone header and a desktop header you write it twice.
svelte-emplace
Every element with that name gets its own copy, and both stay live.
<h1 data-emplace="title"></h1>
<aside data-emplace="title"></aside>

<Emplace to="title">Reports</Emplace>

Crashes show your message

Something that appears in a far-off part of the page can easily fall outside your error handling, leaving a blank screen with nothing to explain it. That does not happen here: the error is caught where the content appears and handed back to the part of your app that opened it.

svelte-portal
Also handled, because the content stays inside your app even though the element moves.
svelte-emplace
Caught at the far end and passed back, so your own message shows and the rest of the page keeps working.
<svelte:boundary>
  {#snippet failed()}
    <p>Could not open</p>
  {/snippet}
  <Emplace><Modal /></Emplace>
</svelte:boundary>

The whole API

<Emplace>…</Emplace>

<Emplace to="title">…</Emplace>

<Emplace to="#tooltips">…</Emplace>

<Emplace to={element}>…</Emplace>

<Emplace to="toolbar" priority={10}>
  …
</Emplace>
No to
It goes to the bottom of the page.
A name
It goes inside any element marked data-emplace="name". If several match, it appears in all of them.
Starts with # . [
Treated as a CSS selector.
An element
It goes inside that exact element.
priority
Higher numbers appear first.

Notes

Not in the first page load

A modal only appears after a click, a tooltip after a hover. So there is nothing to send with the first page load. If you need text in the first HTML, put it in your layout instead. There is no server rendering.

The spot is found once

The spot is looked up when your content appears. If it is not on the page yet, the content goes to the bottom of the page and stays there.
